# Правила работы в репозитории Evolute

## Область работы

- Рабочая область ограничена этим репозиторием. Читай и изменяй файлы за его пределами только с явного разрешения пользователя.
- Развивай существующую интеграцию в `custom_components/evolute`. Не создавай альтернативную интеграцию.
- Меняй только файлы и участки кода, связанные с текущим заданием. Дополнительные исследования и масштабные рефакторинги проводи только при необходимости для него.

## Совместимость и токены

- Храни токены в `ConfigEntry.data` и обновляй их штатным механизмом Home Assistant.
- Сохраняй совместимость существующих `ConfigEntry`, устройств и сущностей, включая их идентификаторы.
- Не меняй схему идентификаторов `ConfigEntry`, устройств и сущностей без отдельного согласования с пользователем и регрессионных тестов совместимости.
- Не выводи в сообщениях и логах и не записывай в отчёты реальные токены, пароли, cookies и другие секреты.

## Git и рабочие системы

- Этот репозиторий — форк `dsultanr/evolute-ha-integration`. `origin` указывает на `regnets1999/evolute-ha-integration`. Сохраняй файлы, унаследованные от upstream, если задание не требует их изменения.
- Выполняй `commit`, `push`, `pull`, `merge`, `rebase`, `reset`, `checkout` и переключение веток только по отдельной команде пользователя.
- Не изменяй настройки Git remotes.
- Сохраняй Git diff и patch-файлы в игнорируемом локальном каталоге для рабочих материалов. Выбирай имена по назначению изменений.
- Перед сохранением diff или patch проверяй, что он не содержит секретов. Создавай такие файлы только для проверки изменений или по явному запросу пользователя, без автоматического сохранения после каждого действия.
- Выполняй развёртывание, перезапуск Home Assistant и действия с реальным автомобилем только с разрешения пользователя.
- Отправляй реальные запросы к API Evolute только с разрешения пользователя. В тестах используй подставные ответы.

## Проверка и документация

- При изменении поведения интеграции добавляй или обновляй тесты.
- При каждой функциональной доработке проверяй, нужно ли обновить корневой `README.md` и соответствующие документы в `docs/`. Если документация не меняется, указывай причину в отчёте.
- Перед завершением запускай доступные релевантные тесты и `git diff --check`.
- Постоянную техническую документацию размещай в `docs/`. Описывай поведение, подтверждённое кодом или воспроизводимой проверкой.
- Храни временные отчёты, материалы review и обезличенные диагностические снимки вне отслеживаемых файлов.

## Выпуск релиза

Соблюдай правила согласования из раздела «Git и рабочие системы». Создавай тег и публикуй релиз только по явному разрешению пользователя.

1. Заверши реализацию и офлайн-тестирование.
2. Проведи review полного diff относительно тега предыдущего релиза.
3. Проверь, что в публикуемых изменениях нет секретов, приватных идентификаторов и сведений о внутренней инфраструктуре.
4. Создай коммит из согласованных изменений и отправь его в `origin/main`.
5. Дождись успешного завершения HACS и hassfest на SHA отправленного коммита.
6. Создай на проверенном SHA аннотированный Git-тег, совпадающий с версией в `manifest.json`, и отправь тег в `origin`.
7. Опубликуй стабильный GitHub Release для этого тега с описанием изменений для пользователей.
8. Проверь, что релиз доступен и опубликованный тег указывает на проверенный коммит.

## Развёртывание

Штатный способ установки и обновления интеграции — встроенный Home Assistant Marketplace. Развёртывание в рабочей системе требует явного разрешения пользователя.

### Обновление через Marketplace

1. После публикации релиза открой Marketplace и страницу интеграции Evolute.
2. Убедись, что Marketplace обнаружил новую версию.
3. Нажми «Обновить».
4. Перезапусти Home Assistant, если Marketplace этого требует.
5. Проверь установленную версию, загрузку интеграции и доступность существующих сущностей.

После предварительного тестового развёртывания `manifest.json` на диске может уже содержать новый номер версии. Marketplace при этом может продолжать показывать предыдущую версию как установленную. Проверяй версию пакета в Marketplace отдельно от версии файлов на диске.

### Внутреннее тестовое развёртывание

- Для предварительного тестирования на HAOS допускается прямое копирование файлов интеграции.
- Перед заменой файлов сделай резервную копию для отката.
- Проверь конфигурацию Home Assistant перед перезапуском Core. Перезапускай Core после успешной проверки.
- Храни адреса, SSH-команды, имена виртуальных машин, пути резервных копий и другие сведения о частной инфраструктуре только в игнорируемом каталоге `.local-work`.
