# Правила работы в репозитории Evolute

## Область работы

- Рабочая область ограничена этим репозиторием. Читай и изменяй файлы за его пределами только с явного разрешения пользователя.
- Развивай существующую интеграцию в `custom_components/evolute`. Не создавай альтернативную интеграцию.
- Меняй только файлы и участки кода, связанные с текущим заданием. Дополнительные исследования и масштабные рефакторинги проводи только при необходимости для него.

## Совместимость и токены

- Храни токены в `ConfigEntry.data` и обновляй их штатным механизмом Home Assistant.
- Сохраняй совместимость существующих `ConfigEntry`, устройств и сущностей, включая их идентификаторы.
- Не меняй схему идентификаторов `ConfigEntry`, устройств и сущностей без отдельного согласования с пользователем и регрессионных тестов совместимости.
- Не выводи в сообщениях и логах и не записывай в отчёты реальные токены, пароли, cookies и другие секреты.

## Git и рабочие системы

- Этот репозиторий — форк `dsultanr/evolute-ha-integration`. `origin` указывает на `regnets1999/evolute-ha-integration`. Сохраняй файлы, унаследованные от upstream, если задание не требует их изменения.
- Выполняй `commit`, `push`, `pull`, `merge`, `rebase`, `reset`, `checkout` и переключение веток только по отдельной команде пользователя.
- Не изменяй настройки Git remotes.
- Все сохраняемые Git diff и patch-файлы размещай в `.local-work/diffs/`. Выбирай понятные имена, отражающие назначение изменений. Не добавляй эти файлы в Git.
- Перед сохранением diff или patch проверяй, что он не содержит секретов. Создавай такие файлы только для проверки изменений или по явному запросу пользователя, без автоматического сохранения после каждого действия.
- Выполняй развёртывание, перезапуск Home Assistant и действия с реальным автомобилем только с разрешения пользователя.
- Отправляй реальные запросы к API Evolute только с разрешения пользователя. В тестах используй подставные ответы.

## Проверка и документация

- При изменении поведения интеграции добавляй или обновляй тесты.
- При каждой функциональной доработке проверяй, нужно ли обновить корневой `README.md` и соответствующие документы в `docs/`. Если документация не меняется, указывай причину в отчёте.
- Перед завершением запускай доступные релевантные тесты и `git diff --check`.
- Постоянную техническую документацию размещай в `docs/`. Описывай поведение, подтверждённое кодом или воспроизводимой проверкой.
- Для локальных рабочих материалов используй `.local-work/`: `reports/` для временных исследований и отчётов, `reviews/` для материалов проверки изменений, `snapshots/` для диагностических снимков без секретов, `temp/` для временных рабочих файлов.

## Общение

- Отвечай пользователю по-русски, кратко и по существу.
- По завершении текущего задания жди следующего поручения пользователя.
