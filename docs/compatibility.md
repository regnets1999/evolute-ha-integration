# Идентификаторы автомобилей Evolute

В версии 1.5.0 серверный `_id` остаётся ключом для запросов API и сопоставления телеметрии. Home Assistant получает независимый случайный UUIDv4 для каждого автомобиля. Домен интеграции `evolute` и ключи сенсоров и кнопок сохранены.

| Поле | Схема 1.5.0 |
| --- | --- |
| `DeviceInfo.identifiers` | `{("evolute", local_uuid)}` |
| `Entity.unique_id` | `evolute_{local_uuid}_{key}` для сенсоров и кнопок. Для трекера — `evolute_{local_uuid}_tracker`. |
| Предложение для `entity_id` | `<платформа>.evolute_{local_uuid}_{key}`. Для трекера — `device_tracker.evolute_{local_uuid}`. UUID записывается без дефисов. |
| Имя устройства и трекера | Название модели и постоянный локальный номер, например `i-Joy 2`. Если модели нет, используется `Evolute` с тем же номером. Имя устройства можно изменить в Home Assistant. |
| Имя записи конфигурации | `Evolute (<модель>)` для одного автомобиля с известной моделью, иначе `Evolute`. |

VIN не передаётся в имена, серийный номер устройства или атрибуты трекера. При проверке метаданных клиент исключает значения, содержащие известный VIN, серверный `_id` или IMEI. Токены и `ConfigEntry.unique_id` аккаунта продолжают обрабатываться по [схеме авторизации](authentication.md).

## Хранение и стабильность UUID

`VehicleIdentityStore` использует `Store` Home Assistant с ключом `evolute.vehicle_identities`. Файл находится в `.storage/evolute.vehicle_identities` внутри конфигурации HA. В нём хранятся соответствия `_id → UUIDv4, локальный номер`. Это приватный файл с серверными ID. Сохраняйте его в резервной копии вместе с реестрами Home Assistant.

Номер уникален для автомобиля в пределах установки. Новые автомобили получают номера после уже сохранённых. Если за один запуск обнаружено несколько новых автомобилей, ключи сортируются перед выдачей номеров. Это исключает зависимость от порядка ответа API. Записи отсутствующих автомобилей сохраняются. Модель для отображения берётся из текущих метаданных, номер остаётся прежним.

Общая для всех записей Evolute блокировка охватывает чтение, выделение ID, атомарную запись и контрольное чтение. Только после подтверждения записи создаются сущности. Повреждённый или недоступный файл откладывает загрузку через `ConfigEntryNotReady`. Если Home Assistant переименовал повреждённый файл, наличие `.corrupt.*` блокирует создание нового. При сбое восстановите исправный файл из резервной копии.

Перезапуск, reload и reauth сохраняют UUID при доступном хранилище и прежнем серверном `_id`. Удаление конфигурационной записи Evolute само по себе не удаляет хранилище UUID. При утрате таблицы без возможности восстановить её или при смене серверного `_id` UUID могут измениться. Для сохранения вручную переименованных `entity_id`, привязок и истории нужны также соответствующие реестры и данные Home Assistant. [Реестр сущностей Home Assistant](https://contributors.home-assistant.io/core/entities/registry/)

## Переход с версии 1.4.3

Оригинал использовал серверный `_id` в `DeviceInfo.identifiers` и `Entity.unique_id`. В 1.5.0 эти ключи меняются. Старые записи устройств, сущностей и `entity_id` не мигрируют. После публикации релиза подготовьте установку и откат. Непосредственно перед началом перехода сделайте свежий backup VM100 в Proxmox. [Порядок чистой установки и отката](marketplace.md#переход-с-исходного-репозитория)
