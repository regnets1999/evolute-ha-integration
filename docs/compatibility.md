# Совместимость идентификаторов при обновлении Evolute

Сравнение выполнено между `fb87fcc` (Evolute 1.4.3) и текущим кодом форка. Для перехода на форк заменяйте код интеграции на месте в `custom_components/evolute`, сохраняя существующую запись конфигурации Home Assistant и его реестры. Домен интеграции остаётся `evolute`.

## Какие идентификаторы сохраняются

| Идентификатор | Evolute 1.4.3 и текущий форк |
| --- | --- |
| `ConfigEntry.entry_id` | Выдаётся Home Assistant при создании записи. Загрузка и выгрузка используют существующий `entry_id` для привязки координатора и платформ. Reauth обновляет `ConfigEntry.data` и перезагружает ту же запись. |
| `ConfigEntry.unique_id` | В 1.4.3 при создании использовался ID аккаунта, а при его отсутствии — фрагмент refresh-токена. Форк для новых записей требует подтверждённый ID аккаунта из access JWT. Существующий `unique_id` остаётся прежним, включая legacy-значение или его отсутствие. Миграция записи не требуется. |
| `DeviceInfo.identifiers` | `{("evolute", car_id)}` в `entity.py`. `car_id` берётся из `_id` автомобиля в ответе API. VIN передаётся как серийный номер устройства. |
| `Entity.unique_id` | `evolute_{car_id}_{key}` для `sensor`, `binary_sensor` и `button`. Для трекера — `evolute_{car_id}_tracker`. Ключи сущностей версии 1.4.3 сохранены. |
| Предлагаемый `entity_id` | `<платформа>.evolute_{car_id}_{key}` для `sensor`, `binary_sensor` и `button`. Для трекера — `device_tracker.evolute_{car_id}`. Например, бинарный сенсор зарядки использует ключ `charging`. |

Реестр сущностей Home Assistant ищет запись по тройке «домен сущности, домен интеграции, `Entity.unique_id`» и использует сохранённый `entity_id`. Поэтому при обновлении на месте сохраняются и исходные имена, и имена, изменённые пользователем. `ConfigEntry.unique_id` служит для идентификации записи аккаунта и не входит в ключ поиска сущности. [Документация реестра Home Assistant](https://contributors.home-assistant.io/core/entities/registry/)

## Условия сохранения `entity_id`

- Сохраняются существующая конфигурационная запись, записи реестра сущностей и домен `evolute`. Для сохранения привязок устройств также сохраняйте реестр устройств.
- API возвращает тот же `_id` автомобиля. Ключи сущностей и платформы остаются прежними.
- Удаление и повторное добавление создаёт новую конфигурационную запись. Восстановление старых имён, привязок и истории при этом не гарантируется. То же относится к удалению записей реестра или смене ID автомобиля на стороне API.
- Недоступность API или отказ авторизации может временно помешать загрузке существующих сущностей. Это не требует их переименования. Для восстановления доступа используйте [повторную авторизацию](authentication.md).

Офлайн-тесты запускают код настройки интеграции и всех четырёх платформ с существующим `ConfigEntry` и подставными ответами API. Они сверяют идентификаторы с эталоном `fb87fcc` и моделируют поиск в реестре для обычного и переименованного `entity_id`. Проверка на действующей установке Home Assistant не выполнялась.
