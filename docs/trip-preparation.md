# Подготовка к поездке

[`EvoluteClient._async_update_user_flags()`](../custom_components/evolute/client.py) по-прежнему запрашивает флаги аккаунта. После успешного ответа клиент оставляет `_tagged_buttons_visible` равным `True`. Пустой объект или отсутствие `isSuperAdmin` и `canViewTaggedCarButtons` в ответе больше не скрывает состояние подготовки и само по себе не блокирует её кнопки в Home Assistant. Обработка HTTP-ошибок запроса флагов остаётся прежней.

Для carV2 `_parse_car_info_v2()` читает логическое поле `lastRun.isActive` кнопки `tripPreparationOn` из `buttons[]`. Как и в мобильном приложении, это поле отражает выполнение сценария. Если поле отсутствует или имеет другой тип, датчик показывает `unknown`. Для доступности кнопок в этом случае используется прежняя проверка по `status`.

Интеграция разрешает `PREPARE`, когда кнопка включена и сценарий простаивает, а `CANCEL` — когда сценарий выполняется. Проверки паркинга, доступности автомобиля и центрального замка продолжают применяться. Имена команд carV2 берутся из `activateCommand` и `deactivateCommand`, а результат отправки определяется ответом Evolute.

Для legacy tbox состояние по-прежнему берётся из `preparation_script`. Логика отправки команд и обработки телеметрии legacy не менялась.

При запуске carV2 координатор берёт `prep_script_time` текущего автомобиля из последнего опроса `/car-service/car/v2/search`. Положительное целое число передаётся как `durationMinutes` в POST запуска. Если сервер прислал список `availableScriptTime`, значение должно входить в него. При отсутствии или некорректном значении поле опускается. Дополнительный запрос или PUT не нужен.
