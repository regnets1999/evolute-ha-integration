# Подготовка к поездке

[`EvoluteClient._async_update_user_flags()`](../custom_components/evolute/client.py) по-прежнему запрашивает флаги аккаунта. После успешного ответа клиент оставляет `_tagged_buttons_visible` равным `True`. Пустой объект или отсутствие `isSuperAdmin` и `canViewTaggedCarButtons` в ответе больше не скрывает состояние подготовки и само по себе не блокирует её кнопки в Home Assistant. Обработка HTTP-ошибок запроса флагов остаётся прежней.

Для carV2 `_parse_car_info_v2()` читает логическое поле `lastRun.isActive` кнопки `tripPreparationOn` из `buttons[]`. Как и в мобильном приложении, это поле отражает выполнение сценария. Если поле отсутствует или имеет другой тип, датчик показывает `unknown`. Для доступности кнопок в этом случае используется прежняя проверка по `status`.

Интеграция разрешает `PREPARE`, когда кнопка включена и сценарий простаивает, а `CANCEL` — когда сценарий выполняется. Проверки паркинга, доступности автомобиля и центрального замка продолжают применяться. Имена команд carV2 берутся из `activateCommand` и `deactivateCommand`, а результат отправки определяется ответом Evolute.

Для legacy tbox состояние, начало и окончание по-прежнему берутся из `preparation_script`.

## Начало и ожидаемое окончание

В carV2 датчик **Trip Preparation Started** использует `lastRun.startedAt` как Unix-время в миллисекундах. Датчик **Trip Preparation End Time** показывает ожидаемый срок окончания в ISO 8601 UTC. Он складывает начало и настроенную длительность `currentScriptTime` в минутах. Если пригодной настройки нет, используется `lastRun.durationMs`. Оценка фиксируется для данного `startedAt` при первом успешном расчёте.

Оба значения очищаются при подтверждённом завершении, истечении оценки или потере подтверждения по телеметрии. После сбоя опроса требуется ответ с данными о цикле, чтобы показать время снова. Ответ HTTP 304 сохраняет ещё действующую оценку и не возобновляет завершённый цикл. Расчётный срок не меняет состояние **Preparing For Trip**. Кодовое имя `prep_end_time` и идентификатор сущности сохранены. Если имя задано пользователем в реестре, Home Assistant может продолжить показывать его.

При запуске carV2 координатор берёт `prep_script_time` текущего автомобиля из опубликованного состояния. Положительное целое число передаётся как `durationMinutes` в POST запуска. Если сервер прислал список `availableScriptTime`, значение должно входить в него. При отсутствии или некорректном значении поле опускается. Маршрут legacy и тело запроса запуска остаются прежними.

## Настройка продолжительности

**Trip Preparation Duration** типа `select` показывает положительные целые варианты из `availableScriptTime` в минутах и отображает `currentScriptTime`, когда оно входит в список. Если текущее значение отсутствует или выходит за пределы списка, состояние выбора неизвестно. Числовой датчик продолжительности сохраняется.

Запись доступна при подтверждённой поддержке и непустом списке вариантов. Для carV2 интеграция проверяет `enabled` кнопки подготовки, для legacy — `preparation_script.available`. Подтверждённый активный цикл блокирует изменение. Доступность записи также зависит от разрешений Evolute для аккаунта и автомобиля.

Интеграция отправляет `PUT /car-service/car/v2/{vehicleId}` с единственным полем `currentScriptTime`. После успешной записи она сразу обновляет координатор и числовой датчик, затем сверяет значение запросом `GET` к той же карточке автомобиля. При расхождении отображается значение из контрольного чтения. При сбое чтения сохраняется значение, принятое PUT. Сбой PUT оставляет предыдущее подтверждённое значение. Длительность хранится на сервере Evolute.

Опрос деталей и запись синхронизированы, поэтому уже начатый опрос не возвращает старую длительность после записи. Если запуск того же автомобиля ожидает завершения записи, carV2 использует значение после сверки либо значение, принятое PUT при сбое чтения. Выбор длительности сам по себе не запускает подготовку.
