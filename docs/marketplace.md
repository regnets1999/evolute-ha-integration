# Публикация форка в Marketplace

Home Assistant 2026.11 включает Marketplace, который использует `hacs.json` в корне репозитория. Форк содержит одну интеграцию в `custom_components/evolute/`. В этом каталоге находятся `manifest.json`, модули, переводы и ресурсы Lovelace. Версия поставляется из архива GitHub, отдельный ZIP-ассет не требуется. [Структура репозитория](https://contributors.home-assistant.io/marketplace/reference/repository-structure/) · [Схема `hacs.json`](https://contributors.home-assistant.io/marketplace/reference/hacs-json/)

## Версия и выпуск

- Форк использует SemVer. Тег стабильного выпуска совпадает с `version` в `manifest.json`. Первый выпуск форка — [1.5.0](release-1.5.0.md).
- `homeassistant: 2026.11.0` в `hacs.json` задаёт нижнюю границу целевого выпуска. Marketplace проверяет её для репозитория с GitHub Releases. Без опубликованного релиза пользовательский репозиторий может предлагать текущий коммит ветки по умолчанию.
- `CARD_VERSION` управляет обновлением кэша JavaScript-карточки и версионируется отдельно. [Правила выпуска Marketplace](https://contributors.home-assistant.io/marketplace/guides/releases/)

## Добавление по ссылке и общий каталог

Форк можно добавить в Marketplace по ссылке. Перед установкой проверьте, что открыта карточка `regnets1999/evolute-ha-integration` и выбран нужный релиз.

Публикация в общем каталоге требует отдельной заявки. [Требования каталога](https://contributors.home-assistant.io/marketplace/guides/catalog/)

## Переход с исходного репозитория

Marketplace 2026.11 блокирует установку репозитория, если тот же домен уже принадлежит другому установленному репозиторию. Безопасная смена владельца с `dsultanr/evolute-ha-integration` на отдельный форк без удаления `ConfigEntry` не подтверждена. [Проверка владельца в Core 2026.11.1](https://github.com/home-assistant/core/blob/2026.11.1/homeassistant/components/marketplace/repositories/integration.py#L154-L171)

Версия 1.5.0 использует локальные UUID. Старые устройства, сущности и `entity_id` не мигрируют. [Совместимость идентификаторов](compatibility.md)

1. Сохраните список используемых `entity_id` и связанных автоматизаций, скриптов и дашбордов. Перед удалением записи создайте резервную копию Home Assistant с конфигурацией и реестрами. Проверьте, что копия доступна для восстановления.
2. В Home Assistant откройте **Настройки → Устройства и службы** и удалите конфигурационную запись исходной интеграции.
3. Удалите пакет `dsultanr/evolute-ha-integration` через **Настройки → Marketplace**. Если Home Assistant предложит удалить пакет сразу после удаления записи, подтвердите и проверьте, что исходный пакет больше не установлен. [Удаление пакетов Marketplace](https://www.home-assistant.io/integrations/marketplace/#uninstalling-content)
4. В Marketplace выберите **Add from link** и добавьте `https://github.com/regnets1999/evolute-ha-integration`.
5. Установите опубликованный стабильный выпуск форка, выполните предложенный Home Assistant перезапуск и заново настройте Evolute. [Инструкция по установке](../INSTALLATION.md)
6. Проверьте, что Marketplace показывает выбранную версию репозитория `regnets1999/evolute-ha-integration`. Проверьте устройства и телеметрию, затем обновите ссылки на новые `entity_id` и проверьте связанные автоматизации и дашборды.

### Откат

Если нужно вернуть прежнюю запись вместе с реестрами, восстановите резервную копию, созданную перед переходом. При полном восстановлении другие данные Home Assistant также вернутся к состоянию на момент копирования. После запуска проверьте исходный пакет Evolute, запись, устройства и автоматизации.

Если сохранение старых `entity_id` обязательно, отложите переход на 1.5.0 до появления согласованной миграции. Ручная замена каталога с сохранением `ConfigEntry` также использует новую схему идентификаторов.
